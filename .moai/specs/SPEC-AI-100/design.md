# SPEC-AI-100 Design — 지평(horizon) 분리 아키텍처 결정

> Tier L 컨벤션에 따라 이 SPEC이 다루는 아키텍처 결정 자체를 문서화한다. First
> Principles(가정 감사 → 분해 → 대안 생성 → 트레이드오프 분석 → 인지 편향 점검) +
> Diverge-Converge 프레임워크를 적용했다.

## §A. 가정 감사 (First Principles Phase 1)

기존 아키텍처(단일 앙상블 + 단일 임계값)를 지탱하는 암묵적 가정을 나열하고 검증한다.

| 가정 | 검증 결과 |
|------|-----------|
| "탐지기 점수는 동일 시점에 대한 예측이므로 합산 가능하다" | **거짓** — research.md §1-2/§2-4가 확인했듯 theme_cluster(48h), momentum_continuation(T-1), volume_breakout(당일)은 서로 다른 시간축의 신호다. 합산은 시간축이 다른 값을 암묵적으로 동일 축으로 투영한다. |
| "레짐별 고정 임계값(BULL/SIDEWAYS/BEAR)이면 충분하다" | **부분 참** — 시장 국면 축은 유효하지만 지평 축과 직교(orthogonal)한다. 레짐 축만 조정하는 현재 설계는 지평 축의 이질성을 전혀 반영하지 못한다. |
| "`horizon` 메타데이터 필드가 이미 지평을 구분하고 있다" | **거짓, 정정됨** — research.md §2-4: 이 필드는 즉각 공시 탐지기 1개 경로에만 존재하며, 일반적인 탐지기-지평 taxonomy가 아니다. |
| "8개 탐지기 모두 실제로 매매 시그널에 기여한다" | **거짓, 신규 발견** — research.md §2-1/§2-2: weekend_gap_up과 bollinger_squeeze는 완전한 고아 탐지기로, 앙상블 스코어링이나 FundSignal 생성 어디에도 연결되지 않는다. |

## §B. 대안 생성 (First Principles Phase 3 + Diverge)

정확히 2개 옵션을 심층 비교한다(위임 프롬프트가 요구한 최소 2개 옵션).

### 옵션 (a) — 완전 분리형: 지평별 독립 스코어링 파이프라인

각 탐지기가 지평(same_day / next_day / multi_day)을 선언하고, 지평별로 **독립된
가중치 세트 + 독립된 임계값 세트**를 유지한다. `compute_ensemble_score` 하나를
지평별 스코어링 함수 2-3개로 교체하고, 각각 자신의 qualified 집합을 만든 뒤 병합한다.

**구조적 난점**: 한 종목이 같은 날 여러 지평의 시그널을 동시에 받을 수 있다(예:
theme_cluster(다일)와 volume_breakout(당일)이 같은 종목에 동시 발화). "완전 분리"는
후보를 지평별로 정확히 1개 버킷에 배정할지, 관련된 모든 지평 파이프라인에서 각각
채점할지에 대한 새로운 병합/중복제거 로직을 요구한다 — 이는 위임 프롬프트가 요구한
"어느 쪽이든 대안의 트레이드오프를 문서화"에 해당하는 첫 번째 근본적 비용이다.

### 옵션 (b) — 지평 태깅형: 단일 파이프라인 + 지평 인식 임계값 프로파일

`compute_ensemble_score`의 가중합·컨센서스 배율 수식 자체는 그대로 유지한다(수년간
SPEC-AI-017/018/039/050/065를 거친 수동 튜닝 이력을 보존). 추가하는 것은:

1. 설정에 탐지기별 지평 라벨을 신규 부여(`ensemble.weights`의 각 키에 대응하는
   신규 `ensemble.horizon_labels` 맵 — 예: `theme_cluster: multi_day`,
   `volume_news_combo: same_day`, `disclosure_pattern: same_day`,
   `news_delayed: multi_day`, `volume_breakout: same_day`,
   `momentum_continuation: next_day`).
2. 후보별 **지평 시그니처**를 계산한다 — `compute_ensemble_score`가 이미 계산하는
   `detector_groups`(news/disclosure/technical, 1576-1584행)와 `active_groups`
   메커니즘을 재사용/확장하여, 어떤 지평의 탐지기가 그 후보에 대해 실제로 발화했는지
   식별한다(전혀 새로운 메커니즘이 아니라 기존 그룹핑 로직의 일반화).
3. 임계값 선택을 지평 시그니처 기반으로 분기한다 — 기존 `effective_threshold`
   (레짐별 단일 표, 2184-2186행) 선택 로직을 "레짐 × 지평 시그니처" 2축 조회로
   확장한다. 가중합·컨센서스 배율·3개 bypass 루프·`combo_chase_guard`·
   `sector_contagion` 게이트는 완전히 무수정이다.

## §C. 트레이드오프 분석 (First Principles Phase 4)

| 축 | 옵션 (a) 완전 분리 | 옵션 (b) 지평 태깅 |
|----|---------------------|----------------------|
| 정확성 | 이론적으로 더 높음 (지평 간 완전 독립) | 옵션 (a) 대비 약 80% 정확성 이득을 20% 구현 비용으로 확보 — 정확한 지평에 정확한 임계값을 적용한다는 핵심 목표는 동일하게 달성 |
| 유지보수성 | **낮음** — 지평별로 가중치를 처음부터 재튜닝해야 하며, 5개 SPEC(017/018/039/050/065)의 수동 튜닝 이력이 무의미해짐 | **높음** — 기존 가중합 공식과 튜닝 이력을 완전히 보존, 임계값 선택 로직만 추가 |
| 검증 용이성 | 낮음 — 별도 파이프라인을 병렬 운영해야 검증 가능, 섀도우 모드 구현 자체가 무거움 | 높음 — 동일 가중합 결과 위에서 임계값 분기만 다르므로, 섀도우 모드(같은 사이클에서 기존 임계값과 신규 임계값을 모두 계산해 diff 로깅)가 자연스럽게 구현됨 |
| 코드 변경 반경 | 큼 — `compute_ensemble_score`의 호출부 3곳(메인 루프 + 정렬), 3개 bypass 루프, `combo_chase_guard`, `sector_contagion` 게이트 전부 재작성 필요 | 작음 — `compute_ensemble_score` 본체 무수정, 신규 함수(지평 시그니처 계산 + 임계값 선택) 추가만 필요 |
| 기존 아키텍처와의 정합성 | 낮음 — 완전히 새로운 개념 도입 | **높음** — research.md §2-4가 확인한 기존 `horizon` 메타데이터 필드(공시 탐지기 한정)와 `detector_groups`(news/disclosure/technical) 메커니즘을 **일반화**하는 방향이며, 코드베이스가 이미 이 방향으로 절반쯤 와 있음을 시사 |
| 롤백 용이성 | 중간 — 이동 부품이 많아 롤백 시 되돌릴 지점이 많음 | 높음 — feature flag 1개로 즉시 기존 동작과 바이트 동일하게 복귀 |

## §D. 인지 편향 점검 (First Principles Phase 5)

"옵션 (b)가 더 저렴하니 선호한다"는 단순 앵커링이 아님을 확인한다: §C의 "기존
아키텍처와의 정합성" 행이 독립적 증거다 — `detector_groups`와 `horizon` 필드라는
**이미 존재하는 메커니즘**이 옵션 (b)의 방향과 구조적으로 일치한다는 사실은, 저비용
때문이 아니라 코드베이스 자체의 기존 설계 궤적이 옵션 (b)를 가리키기 때문에 채택
근거가 된다. 확증 편향 점검: 옵션 (a)가 우월한 시나리오(지평 간 완전 독립이 필수적인
경우, 예를 들어 두 지평이 서로 상쇄 관계인 경우)를 명시적으로 고려했으나, 현재
탐지기 구성에서 그런 상쇄 관계의 증거는 발견되지 않았다(오히려 `combo_chase_guard`가
서로 다른 지평의 탐지기를 corroboration 관계로 취급하는 것은 상호 보완적 관계를
시사한다 — §E 참고).

## §E. 결정 — 옵션 (b) 채택

**옵션 (b) 지평 태깅형 단일 파이프라인**을 채택한다. 근거는 §C-D의 트레이드오프
분석 전체이며, 특히 (1) 수동 튜닝 이력 보존, (2) 검증 용이성(섀도우 모드가 자연스럽게
구현 가능), (3) 기존 코드 메커니즘(`detector_groups`, `horizon` 필드)과의 구조적
정합성이 결정적이다.

**기각한 대안 — 옵션 (a) 완전 분리형.** §C 표 전체가 기각 근거다. 특히 유지보수성
손실(5개 SPEC의 튜닝 이력 무효화)과 검증 난이도 증가가 결정적 요인이다. 옵션 (a)는
"이론적 정확성이 더 높다"는 유일한 우위를 가지나, 이는 미검증 가설이며(실측 근거
없음), 현재 코드베이스에 지평 간 상쇄 관계의 증거가 없는 상황에서 그 우위를 실현할
수 있을지도 불확실하다.

## §F. `combo_chase_guard` 재고 (위임 프롬프트 요구사항)

Gate 4(2158-2174행)의 판정 로직 자체는 **무수정**으로 유지한다. research.md §4가
확인했듯 이 게이트는 이미 서로 다른 지평의 탐지기(theme_cluster=다일,
immediate_disclosure=당일)를 동등한 corroboration 신호로 취급하는데, 이는 "지평 무관
corroboration"이라는 설계 의도로 읽히며 옵션 (b) 도입으로 바뀔 이유가 없다. 유일한
변경점은 **평가 순서의 명시적 문서화**다 — Gate 4는 여전히 임계값 선택 이전에
실행되며(merged 딕셔너리에서 제거), 그 이후 살아남은 후보에 대해서만 지평 시그니처
계산 및 임계값 선택이 이루어진다. 이 순서는 이미 코드의 자연스러운 실행 순서이므로
새로운 제약을 추가하는 것이 아니라, REQ로 명문화하는 것이다.

## §G. `surge_threshold_service`(적응형 임계값)와의 관계 (위임 프롬프트 요구사항)

**독립 유지를 결정한다.** `surge_threshold_service`는 매수 실행 게이트 전용
(execution-only, SPEC-AI-092 REQ-AI092-005로 이미 확정)이며, 옵션 (b)의 지평
인식 임계값은 전적으로 **예측 생성 게이트**(`effective_threshold`) 측의 확장이다.
두 시스템을 병합하면 "이것이 후보가 될 자격이 있는가"(생성 시점)와 "지금 자본을
투입할 것인가"(실행 시점, 자본 가용성 인식)라는 이미 설계된 분리를 흐리게 한다.
기각한 대안 — 두 임계값 체계 통합. SPEC-AI-092가 이미 명명·로그 분리까지 확정한
설계 결정을 되돌릴 근거가 없어 기각한다.

## §H. 고아 탐지기(weekend_gap_up, bollinger_squeeze) 처리 범위 (신규 발견에 대한 결정)

research.md §2-1/§2-2가 발견한 2개 미배선 탐지기는 **본 SPEC의 범위에서 명시적으로
제외**한다(§Out of Scope). 옵션 (b)의 지평 시그니처 메커니즘은 설계상 확장 가능하다 —
이 두 탐지기가 향후 라이브 파이프라인에 배선되는 시점에는 `ensemble.horizon_labels`에
항목을 추가하는 것만으로 편입 가능하다. 그러나 "미배선 탐지기를 배선하는 작업"과
"스코어링 아키텍처를 지평 인식으로 재설계하는 작업"은 성격이 다른 독립적 엔지니어링
과제이며, 이번 Tier L SPEC의 범위를 인위적으로 확장하는 것을 피하기 위해 분리한다.

## §I. 마이그레이션/롤아웃 계획 (위임 프롬프트 요구사항)

1. **Feature flag 게이팅**: `ensemble.horizon_aware_thresholds.enabled: false`
   기본값. 비활성 시 동작은 현재와 바이트 동일(기존 `effective_threshold` 단일 조회
   경로 유지) — 이 프로젝트의 기존 롤아웃 관례(SPEC-AI-079 `relative_threshold_enabled`,
   SPEC-AI-084/091 `theme_news_carry` 플래그)와 일치한다.
2. **섀도우 모드 검증**: 플래그 활성화 전, 매 스코어링 사이클마다 기존 임계값 경로와
   신규 지평 인식 임계값 경로를 **모두** 계산하고, qualified 집합의 차이(추가/제외된
   종목)를 구조화 로그로 기록한다. N 거래일(기본 제안 10일, Open Question 3) 관찰 후
   플래그 전환 여부를 결정한다.
3. **SPEC-AI-099와의 연계**(research.md §6): SPEC-AI-099의 피처 스냅샷이 완료되면
   과거 사이클의 원시 스코어링 결과를 실제로 재구성해 백테스트할 수 있게 되어 섀도우
   모드보다 강한 검증이 가능해진다 — 두 SPEC은 서로를 요구하지 않는 독립 병행
   관계이나, 검증 품질 향상의 수혜 관계다.
4. **평가 지표 대조**: SPEC-AI-095의 `high_based_*` 지표와 표준 T-1→T recall/precision
   지표 양쪽에 대해 플래그 활성화 전후 비교를 수행한다(plan.md §C에서 구체화).

## §J. 롤백

플래그를 `false`로 되돌리면 즉시 기존 동작으로 복귀한다. 신규 DB 마이그레이션이
없으므로(§K 참고) 스키마 롤백 이슈가 없다 — 코드/설정 변경만 되돌리면 완전 복구된다.

## §K. 스키마 영향 범위

이 아키텍처 변경은 **DB 마이그레이션을 요구하지 않는다** — `ensemble.horizon_labels`는
기존 `surge_detection.yaml` 설정 파일에 추가되는 신규 섹션이며, 지평 시그니처 계산과
임계값 선택은 순수 함수 로직이다. 섀도우 모드 로그는 구조화 로그(JSON 라인)로 충분하며,
전용 비교 테이블 신설은 선택적(Open Question, 구현 시 결정)이다.
