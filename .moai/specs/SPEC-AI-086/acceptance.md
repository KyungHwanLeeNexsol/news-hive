# SPEC-AI-086 인수 기준

> [D1] 각 인수 기준(AC)의 정본은 **EARS 문장**이다. 그 아래 "테스트 시나리오(Given/When/Then)"는
> 구현 검증을 위한 내부 교차참조이며, 정본 EARS 문장을 대체하지 않는다.

## Acceptance Criteria (EARS + 테스트 시나리오)

### AC-086-001 (REQ-001, 상한 설정 유연화)
- **EARS**: **While** 스캔 유니버스 상한이 경계 [50, 600] 이내 값(예: 300)으로 설정된 동안, the system
  **shall** 그 상한을 적용하고 최종 유니버스 길이가 그 상한 이하가 되도록 한다.
- 테스트 시나리오: **Given** 상한=300, **When** 유니버스 빌드 실행, **Then** 적용 상한=300 이고 최종
  유니버스 길이 ≤ 300.

### AC-086-002 (REQ-001, 경계 clamp)
- **EARS**: **If** 설정 상한이 경계를 초과(예: 5000)하면, **then** the system **shall** 값을 상한 경계
  (600)로 clamp하고 경고 로그를 남기며 예외 없이 완료한다.
- 테스트 시나리오: **Given** 상한=5000, **When** 유니버스 빌드, **Then** 값이 600으로 clamp + 경고 로그,
  예외 없음.

### AC-086-003 (REQ-007, 백워드 호환) [HARD]
- **EARS**: **While** 신규 설정이 전부 기본값(상한=150, 신규 풀 예약=0, 동적 상한 OFF)인 동안, the system
  **shall** 현재 구현과 바이트 동등한 출력을 낸다.
- 테스트 시나리오: **Given** 신규 설정 전부 기본값, **When** 동일 입력으로 유니버스 빌드, **Then**
  최종 유니버스 순서 · pool_counts가 현재 구현과 바이트 동등.

### AC-086-004 (REQ-002, non_scannable 진단) [HARD]
- **EARS**: **When** non_scannable 진단이 한 거래일의 실제 급등 종목을 대상으로 실행되면, the system
  **shall** 각 non_scannable 종목을 truncated 또는 absent로 분류·기록하며, 신규 마이그레이션 없이 이를
  달성한다.
- 테스트 시나리오: **Given** 급등 종목 A(후보 풀 raw에는 있으나 상한 절단으로 탈락) 및 종목 B(공시·거래량·
  등락 기준 전부 미충족), **When** 진단 실행, **Then** A=truncated, B=absent로 기록(신규 마이그레이션 없이).

### AC-086-005 (REQ-005, 측정 전용 비용 경계) [HARD]
- **EARS**: **If** 확장(상한 상향 또는 신규 풀 활성화)이 유효하면, **then** the system **shall NOT** 기존
  경로의 탐지기 호출 수 · 외부 시세 조회 수 · LLM 발신 호출 수를 확장 전 대비 증가시키며, 측정 유니버스
  코드를 탐지 패스에 투입하지 아니한다.
- 테스트 시나리오: **Given** 확장 유효, **When** 후보 수집(gather) 실행, **Then** 탐지기 호출 수 · Naver
  fetch 수 · LLM 발신 호출 수가 확장 전과 동일하고, 측정 유니버스 코드가 탐지 패스에 미투입됨이 검증됨
  (호출그래프/회귀 assert).

### AC-086-006 (REQ-003, 신규 풀 quota 통합)
- **EARS**: **Where** 신규 풀 예약 슬롯이 설정(예: 20)되고 절단 압력이 존재하면, the system **shall** 그
  풀의 멤버를 최소 예약 슬롯 수만큼 최종 유니버스에 잔존시키고 해당 풀의 entry_pool로 태깅한다.
- 테스트 시나리오: **Given** 신규 풀 예약=20, 신규 풀에 25종목, 절단 압력 존재, **When** 유니버스 빌드,
  **Then** 신규 풀 종목 중 최소 20개가 예약 슬롯으로 잔존하고 entry_pool='pool_d'로 태깅됨.

### AC-086-007 (REQ-006, 지표 정합성 + 명명 필드 검증) [D6]
- **EARS**: **If** scannable 집합이 확장되고 적중(TP)이 불변이면, **then** the system **shall** coverage를
  상승으로, scannable_recall을 하락으로 기록하되, 그 하락이 탐지 회귀가 아님을 **기계적으로 검증 가능한
  명명 필드/토큰**으로 구분 기록한다.
- 테스트 시나리오: **Given** scannable 19→40, TP=3 불변, **When** 평가 실행, **Then** coverage↑ +
  scannable_recall↓ 이 기록되고, 평가 레코드 메타(또는 로그)에 명명 필드 `scannable_denominator_expanded`
  (불리언, 또는 동등 토큰)가 존재하여 "탐지 회귀 아님"을 테스트가 기계적으로 assert 가능.
- 검증 기준(D6): "구분 기록"은 자유 서술이 아니라 **사전에 명명된 필드/토큰의 존재 여부**로 PASS/FAIL을
  판정한다(필드명은 구현 시 확정하되, acceptance가 요구하는 것은 "테스트가 참조할 명명된 표식의 존재").

### AC-086-008 (REQ-004, 장중 시간대별 동적 상한) [D3 신설]
- **EARS**: **Where** 시간대별 동적 상한이 설정되면, the system **shall** 현재 스캔 시각이 속한 시간대에
  할당된 상한을 적용하고, **Where** 미설정이면 the system **shall** REQ-001과 동일한 단일 평탄 상한을 적용한다.
- 테스트 시나리오: **Given** 시간대 상한 맵 {오전 초반→N1, 장 마감 전→N2}, **When** 오전 초반 시각에 빌드,
  **Then** 적용 상한=N1; **When** 동적 상한 미설정, **Then** 단일 평탄 상한(REQ-001 거동) 적용.

### AC-086-009 (REQ-008, 관측성 로그) [D3 신설]
- **EARS**: **Where** 로깅이 유효하면, the system **shall** 적용된 상한 값, 풀별 raw/scanned 카운트, 신규 풀
  카운트, non_scannable 원인 분류 요약을 단일 로그 라인으로 기록하고, 신규 스키마를 도입하지 아니하며
  종목별 상세 로그를 남기지 아니한다.
- 테스트 시나리오: **Given** 유니버스 빌드 1회, **When** 빌드 완료, **Then** 요구 필드(상한 값/풀별
  raw·scanned/신규 풀 카운트/원인 분류 요약)를 포함한 단일 요약 로그 라인 정확히 1줄이 남고, 신규 DB
  스키마 없음 · 종목별 상세 로그 없음.

## 엣지 케이스

- 모든 풀이 비어 있음(주말/장애) → 안전 no-op, 예외 없음.
- 신규 풀 예약 슬롯 합계가 상한 초과 → SPEC-AI-076 clamp 로직으로 비율 축소.
- 신규 풀 소싱 조회 실패 → fail-open(해당 풀 스킵), 나머지 유니버스 정상.
- 동적 상한 맵에 현재 시간대 키 부재 → 단일 평탄 상한으로 폴백(REQ-004 미설정 경로와 동일).
