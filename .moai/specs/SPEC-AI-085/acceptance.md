# SPEC-AI-085 — Acceptance Criteria (인수 기준)

> 각 AC의 **통과 기준은 볼드 처리된 EARS(Easy Approach to Requirements Syntax) 정규 문장**
> (Ubiquitous / Event-Driven / State-Driven / Unwanted / Optional)이다. 각 EARS 문장은 트리거 키워드
> 정확히 1개(**WHEN** / **WHILE** / **IF** / **WHERE** — Ubiquitous는 트리거 없음)와 SHALL/SHALL NOT
> 절 정확히 1개만 포함한다. 하나의 AC가 긍정·부정 거동을 모두 검증하는 경우 각각을 **별도의 EARS
> 문장**으로 분리한다(복합 2-절 문장·em-dash 결합 2차 정규 절·볼드 SHALL과 비형식 모달 혼용 금지 —
> SPEC-AI-081/084 iteration 교정 패턴 준수).
> 각 EARS 문장 아래 _재현 시나리오(비규범)_ 로 표기된 Given-When-Then 블록은 그 기준을 예시하는
> 비규범(non-normative) 서술이며 그 자체가 통과 조건은 아니다. 각 AC는 spec.md의 REQ-AI085-0NN에
> 매핑된다. 운영 모드는 예측 기록(SPEC-AI-043)이며 실매매 미검증.

## 핵심 — 설명 기반 관계 생성

### AC-085-001 (REQ-AI085-001) — 설명 기반 종목 관계 생성 [재현 우선]

- **WHEN** 수집된 기사의 설명(description) 텍스트가 추적 종목의 이름을 포함하고 그 종목이 기사
  제목이나 타깃 검색 쿼리로 명명되지 않으면, the system **SHALL** 그 종목에 대한
  `NewsStockRelation`을 생성해야 한다.

_재현 시나리오(비규범):_
- **Given** 제목엔 종목명이 없고 설명에만 "로보스타"가 등장하는 기사(예: 제목 "로봇주 줄줄이 상한가", 설명 "레인보우로보틱스, 로보스타, 로보티즈 등 로봇 관련주 급등"), `_query=None`
- **When** 크롤 관계 계산이 수행되면
- **Then** 로보스타에 대한 `NewsStockRelation`이 생성된다(설명 매칭 전에는 미생성 = 결손 RED, 매칭 후 GREEN).

### AC-085-002 (REQ-AI085-002) — 종목명 기반(키워드 비의존) 순환 차단

- **WHILE** 설명 기반 관계를 도출하는 동안, the system **SHALL** 관계를 `KeywordIndex.stock_names`
  (종목 이름)으로 도출해야 한다.
- **IF** 대상 종목의 `stocks.keywords`가 NULL/빈 값이면, **THEN** the system **SHALL** 그럼에도
  설명에 종목명이 등장하면 그 종목에 대한 관계를 생성해야 한다(키워드 선채움 비의존).

_재현 시나리오(비규범):_
- **Given** `stocks.keywords`가 NULL인 무-관계 종목의 이름이 어느 기사 설명에 등장
- **When** 설명 기반 관계 계산이 수행되면
- **Then** 키워드가 없어도 종목명 매칭만으로 관계가 생성되어, 그 관계가 이후 `refresh_stock_keywords` 훅으로 키워드 승격까지 자동 연결된다(순환 고리 차단).

### AC-085-003 (REQ-AI085-003) — 이름 경계 가드 + 기사당 상한 [HARD]

- **WHILE** 설명 텍스트에서 종목명을 매칭하는 동안, the system **SHALL** 기존 제목 매처의 이름
  경계 가드(최장일치 우선, 한글 선행문자 배제)를 적용해야 한다.
- **WHILE** 단일 기사에 대해 설명 기반 관계를 생성하는 동안, the system **SHALL NOT** 기사당 설정
  상한을 초과하는 수의 관계를 생성해서는 안 된다.

_재현 시나리오(비규범):_
- **Given** 다수 종목을 나열하는 시황/묶음 기사 설명(예: 20종목 언급) + "하이닉스"를 부분 포함하는 오탐 후보명
- **When** 설명 기반 관계 계산이 수행되면
- **Then** 한글 선행문자로 부분 포함된 오탐은 배제되고(최장일치 + 선행문자 가드), 생성 관계 수가 기사당 상한을 넘지 않는다(남발 방지).

### AC-085-004 (REQ-AI085-004) — 기존 관련성 점수/필터 재사용

- **WHILE** 설명 기반 관계의 관련성을 산정하는 동안, the system **SHALL** 그 관계를 기존
  `calculate_relevance_score` + 최소 점수 필터 경로로 라우팅해야 한다.
- **IF** 설명 기반 관계의 점수가 최소 임계 미만이면, **THEN** the system **SHALL** 그 관계를
  영속화하지 않고 걸러야 한다.

_재현 시나리오(비규범):_
- **Given** 설명 매칭 관계 후보 두 건(하나는 점수 통과, 하나는 임계 미달)
- **When** 관계 삽입 단계가 수행되면
- **Then** 임계 통과 관계만 `news_stock_relations`에 영속화되고 미달 관계는 걸러진다(병렬 점수 게이트 신설 없음).

### AC-085-005 (REQ-AI085-005) — 기존 제목/쿼리 관계 경로 무변경 [HARD]

- **WHILE** 본 SPEC의 변경이 적용된 동안, the system **SHALL NOT** 제목 매칭(`classify_news`)에
  의한 기존 관계 생성을 변경해서는 안 된다.
- **WHILE** 본 SPEC의 변경이 적용된 동안, the system **SHALL NOT** 타깃 쿼리 매칭
  (`_resolve_query_relations`)에 의한 기존 관계 생성을 변경해서는 안 된다.

_재현 시나리오(비규범):_
- **Given** 제목에 종목명이 있는 기사 + 타깃 쿼리로 수집된 기사
- **When** 설명 기반 매칭이 활성인 상태에서 크롤이 수행되면
- **Then** 두 기사의 기존 제목/쿼리 관계는 설명 매칭 도입 전과 동일하게 생성된다(설명 관계는 순수 additive, 기존분 diff 0).

## 롤아웃·안전·데이터 무결성

### AC-085-006 (REQ-AI085-006) — 설정 게이팅 + 단계적 롤아웃

- **WHILE** 설명 기반 매칭 설정 플래그가 OFF인 동안, the system **SHALL** 관계 생성 결과를 기존
  레거시(제목/쿼리 관계만)와 완전히 동일하게 반환해야 한다(플래그 복귀 = 완전 롤백).

_재현 시나리오(비규범):_
- **Given** 설명 기반 매칭 설정 플래그 OFF
- **When** 크롤 관계 계산이 수행되면
- **Then** 설명 기반 관계가 0건이고 나머지 관계 생성 거동은 레거시와 완전 동일하다(롤백 = 플래그 복귀).

### AC-085-007 (REQ-AI085-007) — following/수동 키워드 무오염 [HARD]

- **WHILE** 설명 기반 매칭이 실행되는 동안, the system **SHALL NOT** following 시스템의 사용자
  키워드 데이터를 변경해서는 안 된다.
- **WHILE** 설명 기반 매칭이 실행되는 동안, the system **SHALL NOT** 수동 설정된 `stocks.keywords`를
  무단으로 덮어써서는 안 된다.

_재현 시나리오(비규범):_
- **Given** 수동 설정 `stocks.keywords`를 가진 종목 + following 시스템 사용자 키워드 데이터
- **When** 설명 기반 매칭이 실행되면
- **Then** `news_stock_relations` 행만 기록되고, following 사용자 키워드와 수동 종목 키워드는 전혀 변경되지 않는다.

### AC-085-008 (REQ-AI085-008) — DDD 재현 우선 무회귀

- **IF** 공유 관계 계산 경로(`crawl_all_news` 관계 루프)에 변경이 이루어지면, **THEN** the system
  **SHALL** 그 변경 이전에 현재 거동을 캡처하는 특성화 테스트를 먼저 작성·실행해야 한다(DDD 재현
  우선, CLAUDE.md Rule 4).
- **WHEN** 변경 후 전체 백엔드 스위트가 실행되면, the system **SHALL** 기존 제목/쿼리 관계 생성을
  무회귀로 통과시켜야 한다.

_재현 시나리오(비규범):_
- **Given** 공유 관계 계산 경로 변경
- **When** 변경 전 특성화 테스트를 선행하고 변경 후 전체 스위트를 실행하면
- **Then** 기존 제목/쿼리 관계 생성이 무회귀로 통과하고, 신규 설명 매칭 거동은 신규 테스트로 검증된다.

### AC-085-009 (REQ-AI085-009) — 관측성

- **WHERE** 설명 기반 매칭이 실행되면, the system **SHALL** 크롤당 생성된 설명 기반 관계 수를
  유계 로그로 요약해야 한다(스키마 없음, 종목별 로그 금지).

_재현 시나리오(비규범):_
- **Given** 설명 기반 매칭이 활성인 크롤
- **When** 크롤이 완료되면
- **Then** 그 크롤에서 생성된 설명 기반 관계 수가 유계 요약 로그 1건으로 남는다(순환 고리 차단 효과 관측용).

## 엣지 케이스 (Edge Cases)

- **EC-1** 기사에 설명(description)이 없음(None/빈 문자열) → 설명 매칭 미발화, 제목/쿼리 관계만(오류 없음).
- **EC-2** 설명 매칭 종목이 이미 제목/쿼리로 관계가 있음 → dedup으로 중복 관계 미생성(제목 관계 우선 보존).
- **EC-3** 설명이 부분 포함 오탐명(예: "SK하이닉스" 안의 "이닉스")을 담음 → 한글 선행문자 가드로 배제.
- **EC-4** 설명이 수십 종목을 나열하는 시황 기사 → 기사당 상한으로 관계 수 유계(남발 방지).
- **EC-5** 설명-only 매칭 점수가 최소 임계 미만 → 관계 미영속화(기존 필터 재사용).
- **EC-6** 설명 매칭 종목이 무-관계 필터(`:554-558`)에 걸릴 뻔한 기사를 구제 → 그 기사가 관계와 함께 저장됨.
- **EC-7** 설정 플래그 OFF → 설명 매칭 완전 미발화, 결과가 레거시와 바이트 동일.

## 품질 게이트 (Quality Gates)

- 전체 백엔드 스위트 무회귀: `cd backend && uv run pytest tests/ --tb=short -q -m "not slow"` PASS(신규 테스트 포함, 기존 실패 0 증가).
- 린트 clean: `cd backend && uv run ruff check .`.
- 임포트 sanity: `cd backend && uv run python -c "from app.main import app; print('OK')"`.
- DDD Reproduction-First: 공유 관계 계산 경로 변경 전 RED 특성화 테스트 존재(설명-only 종목이 현재 관계를 못 얻는 결손 캡처) → 변경 후 GREEN.
- 신규 테이블/마이그레이션 0(`news_stock_relations` 기존 테이블/컬럼 재사용, [X-4]).
- 기존 관계 경로 불변: 제목/쿼리 관계 생성 결과 diff 0(AC-085-005).
- 예측 기록 모드 불변: 매매 경로 미트리거([X-5]).

## Definition of Done (완료 정의)

- [ ] AC-085-001~009 전부 볼드 EARS 정규 문장 기준으로 관찰 가능 증거로 통과.
- [ ] 핵심: 설명에만 종목명이 있는 기사가 `NewsStockRelation`을 생성(설명 매칭 전 미생성 RED → 후 GREEN), 종목 이름 기반(키워드 비의존)으로 순환 고리 구조적 차단.
- [ ] 오탐 통제: 이름 경계 가드 + 기사당 상한 + 기존 점수 필터 재사용.
- [ ] 무변경: 기존 제목/쿼리 관계 diff 0, following/수동 키워드 무오염, 신규 마이그레이션 0.
- [ ] 게이팅: 플래그 OFF = 완전 레거시(롤백 검증), 단계적 롤아웃.
- [ ] 전체 스위트 + 린트 통과, 재현 우선 특성화 선행, 무회귀 확인.
- [ ] 관측(후속): 배포 후 설명 기반 관계 생성 수 로그 + 순환 고리 차단 종목 수 관측(범위 밖 계측, §8(c)).
